# Diagnostics Mode — Design

**Goal:** A user-toggleable, session-scoped "Diagnostics Mode" that logs all data-fetch and integration operations (and their errors) between the Code App and Dataverse / Custom APIs to the browser console, to make troubleshooting user-reported issues easier — without leaking secrets.

**Status:** Approved 2026-05-25. Ships on PR #9 branch (`fix/audit-followups-v2` → `dev`) alongside the audit follow-ups.

## Decisions (locked)

| Question | Decision |
|---|---|
| Name | **Diagnostics Mode** |
| Persistence | **Session-scoped** — `sessionStorage`; clears when the tab/session closes |
| Who can enable | Any user (logs to their own console) |
| Activation | Settings toggle + `?debug=1` URL param (support can send a link) |
| Log depth | **Metadata + redacted payloads** (best-effort redaction; residual PII accepted) |
| Sink | **Browser console only** (`console.debug` / `console.groupCollapsed`) |
| Schema change | None (session-only; no Dataverse field) |

## Architecture

Everything funnels through one TanStack `QueryClient` (reads via `useQuery`, writes/Custom-APIs via `useMutation`). That is the single choke point.

### `src/lib/diagnostics.ts`
- State in `sessionStorage["enmax.diagnostics"]` (`"on"`/absent).
- `isDiagnosticsOn(): boolean` — for non-React callers (cache handlers).
- `setDiagnostics(on: boolean): void`.
- `useDiagnostics(): { on: boolean; setOn: (b:boolean)=>void }` — React hook (subscribes via a tiny event so the indicator + toggle stay in sync).
- `diagLog(category, summary, details)` — no-op when off; otherwise `console.groupCollapsed("[diag] " + summary)` + `console.debug(redact(details))` + `groupEnd`.
- `redact(value)` — deep-clone + mask (see below).
- `?debug=1` (or `?diagnostics=1`) read once at boot → `setDiagnostics(true)`.

### `redact(value)` — the secret/PII boundary
Deep-walk a clone and:
- Mask any object key matching `/(token|secret|password|authorization|bearer|api[-_]?key|client[-_]?secret)/i` → `"***"`.
- Mask PII keys matching `/(email|upn|userprincipalname|fullname)/i` → `"***"`.
- **App Configuration rows** (entity `enmax_autocadappconfigs`): mask `enmax_acdnvalue` → `"***"` (mailbox, SP URL, team GUIDs).
- Truncate strings > 500 chars and arrays > 50 items (note the elision).
- Documented as **best-effort**: a denylist cannot guarantee zero PII; this is the accepted trade for the "metadata + redacted payloads" choice.

### `main.tsx` — global cache handlers (gated on `isDiagnosticsOn()`)
- `QueryCache` `onSuccess(data, query)` → `diagLog("read", "<queryKey[0]> (<rowCount> rows)", { key, params, result })`.
- `QueryCache` `onError(error, query)` → `diagLog("read:error", ..., { key, error })`.
- `MutationCache` `onSuccess/onError(_, variables, _, mutation)` → `diagLog("write", "<mutationKey|fn>", { variables, result|error })`.
- Row count + best-effort duration from query state.

### UI
- **Settings page**: a "Diagnostics Mode" `Switch` (session-scoped) + help text: "Logs data & API operations to the browser console for troubleshooting. Secrets are redacted. Turns off when you close the tab."
- **Indicator**: a small persistent chip ("Diagnostics on") in the app chrome (header or footer) so the mode is never left running unnoticed.

## Out of scope
- Generated service files (autogenerated — not edited).
- SharePoint direct calls (none today; only rendered links).
- Persisted/cross-device toggle, admin global flag, in-app log buffer/export (can be a later iteration).

## Testing
- `redact()`: masks token/secret/email/fullname keys + app-config `enmax_acdnvalue`; preserves codes/filters/GUIDs; truncates oversize values.
- Gating: `diagLog` is a no-op when off (spy on console).
- Activation: `?debug=1` turns it on; toggle reflects + persists for the session.
- Indicator renders only when on.

## Security guarantees
- Auth tokens are owned by the Power Apps host; app code never sees them, so they cannot appear in logs.
- App Config values are masked.
- Console-only; nothing transmitted off the client.
