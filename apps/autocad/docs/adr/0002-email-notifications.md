# ADR 0002: Email notification routing

## Context

Reservation, checkout, and check-in workflows already create in-app notifications via plug-ins. Email was partially implemented for reservation approval only, with broken recipient resolution (display names used instead of `internalemailaddress`) and approval mail fan-out to individual team members.

ENMAX Document Control (`GWE-DocControl@enmax.com`) must receive all approval requests directly, and must be CC'd on creator-facing lifecycle emails (checkout / check-in).

## Decision

1. **App Config keys**
   - `DocControlEmailAddress` — approval mail **To**; CC on creator lifecycle mail
   - `CodeAppBaseUrl` — deep links in HTML email bodies

2. **Shared child flow** `Child_Send_System_Email` — parameterized To / Cc / Subject / BodyHtml from shared mailbox.

3. **Reservation approval**
   - `On_Reservation_Created_Notify_Admins` sends one approval-needed email **To** DocControl (in-app notifications to approver/admin teams unchanged).
   - Approved/declined result emails go **To** reservation `createdby` user email, **Cc** DocControl.

4. **Checkout / check-in** (new flows on `enmax_autocadcheckout`)
   - `On_Checkout_Created_Email_Notifications` — Requested → DocControl; Open → creator + CC DocControl.
   - `On_Checkout_Updated_Email_Notifications` — Open (after approval) → creator + CC; Awaiting Validation → DocControl + creator + CC; Closed Approved (direct check-in) → creator + CC.
   - Checkout-update must **not** exclude `ServiceAccountUserId` / SYSTEM `modifiedby`: plugin lifecycle writes use elevated SYSTEM context, so a reservation-style loop-guard would suppress the mail. The child send flow has no write-back loop.
   - Caller-controlled HTML fields (submission info, display names) are escaped in parent BodyHtml; `Child_Send_System_Email` terminates when SharedMailbox or To is empty.

5. **Recipient resolution** — reservation creator = `enmax_autocadreservation.createdby` → `systemuser.internalemailaddress`, reached via drawing → reservation lookup.

6. **Connection references** — email, SharePoint indexer, and Teams adaptive-card flows bind to the solution connection references in `enmax_autocadsln`:
   - `enmax_autocadconrefDataverse` (Microsoft Dataverse)
   - `enmax_autocadconrefOutlook` (Office 365 Outlook, shared mailbox send)
   - `enmax_autocadconrefSharePoint` (SharePoint Online, indexer/UAT flows)
   - `enmax_autocadconrefTeams` (Microsoft Teams, reservation approval adaptive cards)

   Source: `solution/src/Workflows/*/workflow.json` (generated by `solution/scripts/build_workflow_clientdata.py` from `definition.json`). Import or update flows using `workflow.json`, not `definition.json` alone.

## Consequences

- Flows must be imported/enabled in each environment after solution deploy; `pp-deploy flows` remains a stub.
- `CodeAppBaseUrl` must be set per environment to the published Code App URL.
- `SharedMailboxAddress` defaults to `EEC_PwrPlat_Svc@enmax.com` in DEV/UAT seed; all child mail flows read it from App Config (not flow parameters).
- Checkout flows no-op if drawing has no reservation link (Get Reservation step fails); legacy rows without reservation should be rare post-issuance.

## Alternatives considered

- **Plug-in Exchange send** — rejected; no durable mail connector in plug-in sandbox, duplicates existing Power Automate pattern.
- **Email every approver team member** — rejected per Document Control routing requirement.
